## 実装後の振り返り

### 実装完了日

2026-08-14

### 計画と実績の差分

**計画と異なった点**:

- **拡大の上限を cover 基準に据え直した。** 当初は「下限だけ差し替える」つもりだったが、
  上限も `minZoom * 8` と下限からの相対で計算していたため、contain に切り替えると
  上限まで一緒に下がってしまうことに実装中に気づいた。
  横長の画像（FHD スクショなど）では contain が cover の 42% しかないので、
  上限も 42% に落ちて「全体を表示にすると拡大できない」状態になっていた。
  上限は `coverZoom * 8` と明示的に cover 基準へ固定した。

**新たに必要になったタスク**:

- `commit` の useCallback 依存配列に `page.fitMode` を追加。
  入れ忘れるとモードを切り替えても古い下限でクランプされ続ける。

### 学んだこと

**技術的な学び**:

- **「モードを増やす」より「1 つのパラメータの範囲を変える」ほうが壊れにくい。**
  cover / contain を別々の配置ロジックにすると `clampOffset` にも分岐が要るが、
  「縮小の下限が違うだけ」と捉えると既存の非対称なクランプがそのまま両モードで正しく動いた。
  結果として core 側の追加は関数 2 つだけで済んだ。

- **Clipper が「順序を守れ」と警告していた罠は、構造で消せた。**
  あちらは GUI の状態を順番に書き換える設計だったのでロック解除 → fit の順序が必要だったが、
  store の 1 アクションで原子的に更新すれば、そもそも順序という概念が発生しない。
  移植するときは警告そのものではなく、**警告が必要になった原因**を見るべきだった。

**プロセス上の改善点**:

- 初期セットアップで cover 下限だけ移植して「全体を表示」を落としていたのは、
  Clipper の `lock_min_zoom` という**既定値**だけを見て、それに付随する
  **逃げ道**を見落としたため。既定値を移植するときは、その既定を外す手段が
  元実装にあるかを併せて確認する。

### 次回への改善提案

- ページごとにモードを持たせたが、「全ページ一括で切り替えたい」場面はありそう。
  実機で使ってみて必要なら追加する（今は選択中ページのみ）。
- 余白色は白固定。黒背景のスクリーンショットでは黒余白のほうが自然だが、
  Kindle のスリープ画面用途では白のほうが無難なので現状維持とした。
