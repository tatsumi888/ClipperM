# 要求内容

## 概要

切り抜き枠に対して画像全体を収める「全体を表示」を追加する。現状は縮小の下限が cover 倍率に固定されており、画像全体を 1 ページに入れる手段が存在しない。

## 背景

初期実装では `CropCanvas` の縮小下限を `coverZoom`（枠を隙間なく埋める最小倍率）に固定した。Clipper の `lock_min_zoom` が既定で真なのに揃えたもの。

**しかし Clipper には「全体を表示」ボタンという逃げ道があり、ClipperM にはそれを移植し忘れていた。** その結果、縦横比が枠とほぼ一致する画像以外は全体を 1 ページに収められない。

Paperwhite 第12世代（1264×1680）で、下限まで縮小しても見える範囲:

| 画像 | 寸法 | 見える範囲 |
|---|---|---|
| iPhone スクショ（縦長） | 1290×2796 | 縦 61% |
| iPhone 写真 4:3（縦） | 3024×4032 | 100%（比がほぼ一致） |
| iPhone 写真 4:3（横） | 4032×3024 | 横 56% |
| PC スクショ FHD（横） | 1920×1080 | 横 42% |
| 正方形 | 2000×2000 | 横 75% |

**横向きの写真と PC のスクリーンショットは必ずどこかを捨てることになる。** 本アプリの主用途にはキャプチャ画像が含まれており、「全体を読みたい」要求は普通に発生する。

## 実装対象の機能

### 1. ページごとの表示モード

- 各ページが `cover`（枠を埋める）か `contain`（全体を表示）かを持つ
- 既定は `cover`（従来の挙動を変えない）
- 切り替えは選択中のページに対して行う

### 2. contain モードでの縮小下限の緩和

- `contain` のとき、縮小の下限は `containZoom`（画像全体が枠に収まる最大倍率）になる
- 枠に隙間ができる位置へも offset を置ける（覆えていない軸は中央に固定される）

### 3. 出力への反映

- `contain` のページは出力にも白い余白が入る
- 余白は白。e-ink は白背景であり、EPUB の CSS も既に白なので違和感は小さい

## 受け入れ条件

- [ ] 「全体を表示」を押すと、画像全体が枠に収まる（どちらの軸もはみ出さない）
- [ ] 「枠を埋める」を押すと、枠に隙間ができない状態へ戻る
- [ ] `contain` のページで、その状態より小さくは縮小できない
- [ ] `cover` のページの挙動が従来と変わらない（下限は `coverZoom` のまま）
- [ ] 出力解像度が指定値ちょうどであることは、モードによらず変わらない
- [ ] プリセットを変えても各ページのモードが維持される
- [ ] **モードの切り替えとズームの適用が原子的**で、クランプに巻き戻されない

## スコープ外

- ドラッグでの並べ替え（別件）
- 余白色の選択（白のみ）
- `contain` より更に小さく縮小すること（用途が無い）
