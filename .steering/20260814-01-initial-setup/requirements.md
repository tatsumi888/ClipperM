# 要求内容

## 概要

スマホ上の画像（撮影した写真・スクリーンショットなど）を Kindle 端末の実解像度ちょうどに切り抜き、複数枚をまとめて固定レイアウト EPUB に変換して、Kindle へ送り込む PWA を新規に立ち上げる。

## 背景

デスクトップには既に [Clipper](../../../Clipper/) と [EpubCoverBuilder](../../../EpubCoverBuilder/) があり、

```
画像 → Clipper（指定解像度で切り出し）→ EpubCoverBuilder（1枚=1冊のEPUB化）→ Send to Kindle
```

という流れが確立している。しかし **切り出したい画像の多くはスマホの中にある**（撮影した写真、アプリのスクリーンショット）。現状はスマホ → PC への転送が必ず挟まり、これが実用上の最大の摩擦になっている。

ClipperM はこの流れをスマホ内で完結させる。加えて、EpubCoverBuilder の未対応項目である「複数ページ対応（現状は 1 枚 = 1 EPUB）」をこちらで解決する。

### 制約: 有料サービスを使わない

これは単なる希望ではなく、アーキテクチャを決定する制約である。

- **iOS ネイティブアプリは選択できない**（Apple Developer Program が年 $99）
- したがって **PWA 一択**。画像処理・EPUB 生成をすべて端末内で行えばサーバも不要になり、ホスティングも静的配信の無料枠で足りる
- Kindle への送信は Send to Kindle のメール受信（`@kindle.com`）を使う。Wi-Fi 経由なら配信料金は発生しない

## 実装対象の機能

### 1. 画像の取り込み

- ファイル選択から複数枚の画像を選べる
- Android では OS の「共有」メニューから ClipperM に直接送り込める（Web Share Target）
- HEIC を含むスマホ由来の形式を扱える（ブラウザがデコードできる範囲で）
- EXIF の回転情報を反映して正しい向きで表示する

### 2. 出力解像度ちょうどの切り抜き

- Kindle 各機種の解像度プリセットを選べる（Clipper の `presets.py` と同一の値）
- **切り出し枠は固定し、下の画像を pan / pinch-zoom して構図を決める**（Clipper と同じモデル）
- 出力は常に指定解像度ちょうど。枠に隙間ができない位置へ自動的に押し戻す

### 3. Kindle 表示のシミュレーションと変換

- 16 階調グレースケール + Floyd–Steinberg 誤差拡散を出力解像度でかけられる
- プレビューで白黒の見え方を確認できる

### 4. 複数ページの EPUB 化

- 切り抜いた画像をリストに溜め、順序を入れ替えられる
- まとめて 1 冊の固定レイアウト EPUB として書き出す
- 1 ページ目をカバー画像に設定する（Kindle のスリープ画面に出すため）

### 5. Kindle への送信

- Web Share API でメールアプリに EPUB を渡し、`@kindle.com` 宛に送る
- 共有が使えない環境ではダウンロードにフォールバックする

## 受け入れ条件

### 画像の取り込み

- [ ] ファイル選択で複数枚を追加でき、追加順にリストへ並ぶ
- [ ] EXIF Orientation が 1 以外の画像が正しい向きで表示される
- [ ] Android の共有メニューに ClipperM が現れ、選んだ画像がアプリに渡る

### 切り抜き

- [ ] 出力画像の寸法が、選択したプリセットの値と**完全に一致する**
- [ ] 元画像が枠より小さい場合、zoom > 1.0 に自動調整され余白が出ない
- [ ] pan で枠外に画像を動かしても、枠に隙間ができる位置には止まらない
- [ ] 座標変換 `frame = image * zoom + offset` の単体テストが通る

### EPUB 生成

- [ ] `mimetype` が ZIP の**先頭**エントリで、**無圧縮 (method=0)**、extra field なし、20 バイト丁度である（バイト列を直接検証する）
- [ ] `dc:identifier` が生成ごとに異なる UUID になる
- [ ] `rendition:layout` が `pre-paginated` である
- [ ] 1 ページ目の画像に `properties="cover-image"` が付く
- [ ] 各ページの `viewport` に画像の実寸が書かれている
- [ ] 複数枚を渡すとページ数ぶんの XHTML と画像が入り、spine の順序がリストの順序と一致する

### 送信

- [ ] Web Share API が使える環境では EPUB ファイルが共有シートに渡る
- [ ] 使えない環境ではダウンロードにフォールバックし、処理が失敗しない

## 成功指標

- スマホ内で「画像を選ぶ → 切り抜く → 送る」が**PC を経由せず**完結する
- 生成した EPUB が Kindle で余白・ぼやけなく全画面表示される（実解像度ちょうどのため）
- 動作にサーバも有料サービスも一切要らない

## スコープ外

以下はこのフェーズでは実装しません:

- e-ink のコントラスト圧縮シミュレーション（Clipper の `eink_contrast`）。プレビューの写実性向上であって出力には使わないため、初期リリースには不要
- 切り抜き結果の画像単体での保存（本アプリの目的は EPUB 化）
- EPUB のメタデータ編集 UI（タイトルは入力できるが、著者・言語などは固定）
- 生成した EPUB の端末内での永続保存・履歴管理
- iOS の共有メニューからの取り込み（Web Share Target が iOS Safari 非対応のため技術的に不可能）
