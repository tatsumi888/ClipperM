# 要求内容

## 概要

デプロイ後、開きっぱなしの PWA でも新しい Service Worker に確実に切り替えられるようにする。
あわせて、いま動いているのがどのビルドかをアプリ画面上で確認できるようにする。

## 背景

ClipperM は `registerType: 'autoUpdate'` で `vite-plugin-pwa` を使っているが、実際に新しい
Service Worker を検知するタイミングはブラウザの標準的な更新チェック（ナビゲーション時など）に
依存している。PWA として起動しっぱなし（ホーム画面から開いて長時間閉じない）だと、次にいつ
更新が検知されるか分からない。

さらに、現在の `autoUpdate` の実装（`vite-plugin-pwa` の register.js）は新しい Service Worker が
`activated` した瞬間に**予告なく `window.location.reload()`** する。ClipperM は編集中の状態
（切り抜き位置・ズーム等）をどこにも永続化していないため、これは「送ったつもりで送れていない」
（CLAUDE.md記載の既存の失敗パターン）と同種の、**黙って作業中の状態を失わせる**挙動になっている。

これを避けつつ、デプロイの度に確実に更新を拾えるようにしたい。ただし更新後に
「本当に新しいビルドに切り替わったか」を確認する手段が画面上に無いため、リビジョンと
ビルド日時（JST）を画面に出す。

## 実装対象の機能

### 1. Service Worker の更新をユーザー操作で安全に適用する

- SW の登録を `autoUpdate`（予告なく reload）から `prompt` 相当（ユーザーの操作で適用）に変える
- 起動時・タブがフォアグラウンドに戻ったとき・一定間隔で、新しい SW の有無を確認する
- 新しい SW が見つかったら画面にバナーを出し、ユーザーが「更新する」を押した時だけ
  適用（reload）する。黙って reload しない

### 2. ビルド情報（リビジョン・JST ビルド日時）の画面表示

- ビルド対象の git リビジョン（短縮ハッシュ）をビルド時に埋め込む
- ビルド日時を JST（`Asia/Tokyo`）で埋め込む
- アプリ画面上の常に見える位置（ヘッダー付近）に表示する
- 上記「更新する」を実行して新しいビルドに切り替わったことを、この表示の変化で確認できる

## 受け入れ条件

### Service Worker の更新

- [ ] 新しい SW が `waiting` 状態になったとき、画面に更新バナーが表示される
- [ ] バナーの「更新する」を押すまでは自動で reload されない
- [ ] 「更新する」を押すと SW が適用され、ページが reload される
- [ ] タブを非表示→表示に戻したときに更新確認が走る
- [ ] 一定間隔（1時間）でも更新確認が走る
- [ ] 初回インストール時（既存 SW が無い状態）は従来通り即座に有効化され、
      共有ターゲット等がすぐ使える（バナーは出ない）

### ビルド情報表示

- [ ] アプリ画面に git リビジョン（短縮ハッシュ）が表示される
- [ ] アプリ画面にビルド日時が JST で表示される
- [ ] ローカルで未コミットの変更がある状態でビルドした場合、それが分かる表示になる
- [ ] `npm run build` を実行するたびに値が更新される

## 成功指標

- デプロイ後、実機で「更新する」バナーが出て、押すとビルド情報の表示が新しい値に変わることを
  目視で確認できる

## スコープ外

- 編集中の状態（ページ一覧・切り抜き位置など）の永続化・自動保存は今回は行わない
  （更新バナーをユーザー操作にすることで、reload タイミングをユーザーの制御下に置くことで対処する）
- Service Worker のバージョン管理・キャッシュ名のスキーム自体は変更しない
