# リポジトリ構造定義スキル

このスキルは、明確で保守しやすいリポジトリ構造を定義するための詳細ガイドです。

## 前提条件

リポジトリ構造定義を開始する前に、以下を確認してください:

### 必須ドキュメント

**まず `docs/` を一覧してください。** 番号の有無を問わず、以下3種が存在すればよい:

1. PRD(`product-requirements.md` / `01-product-requirements.md` 等)
2. 機能設計書(`functional-design.md` / `02-functional-design.md` 等)
3. アーキテクチャ設計書(`architecture.md` / `03-architecture.md` 等)

リポジトリ構造は、アーキテクチャ設計で決定された技術スタックとシステム構成を反映した具体的なディレクトリ構造を定義します。

## 既存ドキュメントの優先順位

**重要**: `docs/` に既存のリポジトリ構造定義書がある場合(ファイル名は `repository-structure.md`
でも `04-repository-structure.md` でも構いません)、以下の優先順位に従ってください:

1. **既存のリポジトリ構造定義書** - 最優先
   - プロジェクト固有のディレクトリ構造が記載されている
   - このスキルのガイドより優先する
   - **既存のファイル名・パスをそのまま使う。** 番号付きの新名へリネームしない

2. **このスキルのガイド** - 参考資料
   - 汎用的なテンプレートと例
   - 既存定義書がない場合、または補足として使用

**新規作成時**: このスキルのテンプレートとガイドを参照
**更新時**: 既存定義書の構造と内容を維持しながら、既存のファイル名のまま更新する

## 出力先

**まず `docs/` を一覧してください。** 同種のドキュメント(リポジトリ構造定義書)が既にある場合は、
番号の有無やファイル名の違いを問わず、**そのファイルをそのパスのまま更新します**
(新しいファイルを作らない)。

新規作成時は、以下に保存してください:

```
docs/04-repository-structure.md
```
