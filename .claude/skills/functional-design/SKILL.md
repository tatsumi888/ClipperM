# 機能設計書作成スキル

このスキルは、高品質な機能設計書を作成するための詳細ガイドです。

## 前提条件

機能設計書作成を開始する前に、以下を確認してください:

### PRDが作成されている

**必須**: PRDが `docs/` に存在する必要があります。**まず `docs/` を一覧してください。**
ファイル名は `product-requirements.md` でも `01-product-requirements.md` でも構いません
(番号の有無・名前の細部を問わない)。

機能設計書は、PRDで定義された要件を技術的に実現する方法を詳細化します。

## 既存ドキュメントの優先順位

**重要**: `docs/` に既存の機能設計書がある場合(ファイル名は `functional-design.md` でも
`02-functional-design.md` でも構いません)、以下の優先順位に従ってください:

1. **既存の機能設計書** - 最優先
   - プロジェクト固有の設計が記載されている
   - このスキルのガイドより優先する
   - **既存のファイル名・パスをそのまま使う。** 番号付きの新名へリネームしない

2. **このスキルのガイド** - 参考資料
   - 汎用的なテンプレートと例
   - 既存設計書がない場合、または補足として使用

**新規作成時**: このスキルのテンプレートとガイドを参照
**更新時**: 既存設計書の構造と内容を維持しながら、既存のファイル名のまま更新する

## 出力先

**まず `docs/` を一覧してください。** 同種のドキュメント(機能設計書)が既にある場合は、
番号の有無やファイル名の違いを問わず、**そのファイルをそのパスのまま更新します**
(新しいファイルを作らない)。

新規作成時は、以下に保存してください:

```
docs/02-functional-design.md
```
